Researched 19 Nov 2026 from public pages only (press releases, help centres, trade press, public GitHub
READMEs). No product was logged into or driven live, so every UI detail is from a published description,
not observation. Tags used below:

- **[V]**: verified on a primary source (the vendor's own page or docs) that was fetched.
- **[S]**: secondary source (trade press or a third-party teardown). Plausible, but not checked against the vendor.
- **[U]**: unverified. A single weak source or an inference. Do not repeat it as fact.

"Ours" means this repo: `frontend/components/Chat.tsx`, `frontend/components/Parts.tsx`, and
`frontend/app/evals/page.tsx`, read on 19 Nov 2026.

**What section A shows.** The portals converge on one pattern. Conversational intake leads to a carousel or
map of listing cards that carry **visible data-owner attribution**. Refinement stays in the conversation, and
the transaction (tour, agent, finance) is **handed off out of the chat**. Fair-housing refusals are the only
refusal type the portals publish. Rightmove is the most transparent: a per-message "Sources" button, named
data sources, and compare from up to 5 selected properties. **No Gulf portal has published Arabic-language
support for its AI**, as far as the public record shows [U].

## D. How strong teams present evals

- **Error bars.** Report the standard error under each mean, in parentheses. Use clustered SEs when questions share a source. Clustered SEs can be over 3× naive ones [V, arXiv]. [Miller, *Adding Error Bars to Evals*, arXiv 2411.00640, Nov 2024](https://arxiv.org/abs/2411.00640)
- **Raw instance outputs published next to aggregates** (prompts, completions, run metadata, downloads) [V for the paper, S for the site]. [HELM, arXiv 2211.09110](https://arxiv.org/abs/2211.09110), [docs](https://crfm-helm.readthedocs.io/)
- **Paired metrics that expose the trade-off.** OpenAI's Safety Evaluations Hub shows refusal of harmful prompts (~0.99) next to over-refusal of benign ones (best 0.80), and accuracy next to hallucination rate, with the measurement condition stated ("without browsing") [S]. [eWeek, May 2025](https://www.eweek.com/news/opeai-safety-hub-making-models-secure/)
- **Method disclosed with the number.** Prompt published, outputs released as a dataset, threshold stated (HHEM < 0.5 = hallucination), "last updated" date shown [S]. [Vectara leaderboard via HF](https://huggingface.co/spaces/vectara/leaderboard/blob/main/src/display/about.py)
- **Error analysis before metrics.** Read traces, code the first upstream error, count failure modes, and validate any LLM judge against hand labels [S]. [hamel.dev](https://hamel.dev/notes/llm/ai-product-engineering/evals-error-analysis.html)
- **Model-card framing.** Intended use, out-of-scope use, evaluation data, caveats. [Mitchell et al., arXiv 1810.03993](https://arxiv.org/abs/1810.03993)

## Steal this (ranked by impact for our app, max 15)

Each item is a concrete, checkable change. "Where" refers to our files.

1. **Inline citation chips tied to the source list.** Render `[n]` markers in answer prose as small chips. Clicking one opens a popover with site, title, the excerpt used and the as-of date. *Where:* the answer prose renderer in `Chat.tsx` plus `SourceList` / `SourceRow` in `Parts.tsx`. The prompt in `chat.py:632` already numbers passages `[n]`, but the prose renderer prints plain text and no chip parsing was found [U, verify]. *Why:* our sources sit as a detached footer. Every leader binds claims to sources: Perplexity chips and popover, ChatGPT tap-to-highlight, Claude `cited_text`. Same-brief competitor C3 already does it. It also targets our failing `must_cite` cases (R1, R6) and `citation_rate` 0.88. *Check:* each chip resolves to a listed source, and no chip has a number with no source.
2. **Advisor handoff on cards and after advice refusals.** Add an "Ask a DarGlobal / Wasalt advisor" action that opens the official contact URL. Optionally copy a one-paragraph brief to the clipboard, with nothing stored (SPEC D9/D10). *Where:* `ProjectCard` / `ListingCard` footer and the R5 investment-advice template chips. *Why:* every portal ends in a human handoff (Zillow, Redfin, Realtor.com). Redfin reports about 1 in 10 Ask Redfin users request an agent [V]. *Check:* the R5 reply shows the action in EN and AR.
3. **"Applied filters" chip row above listing results, each chip removable, with a note on what was relaxed.** For example: Riyadh · 2 bed · ≤ 1.5M SAR · *budget widened to 1.65M because nothing matched*. *Where:* above `CardRail` in `Parts.tsx`, fed from the planner's parsed filters. *Why:* it makes the structured parse checkable. Rightmove and Bayut keep classic filters next to AI. C2 states which filter it relaxed, and C3 links each requirement to the user's words. *Check:* removing a chip re-runs the search without that filter.
4. **Answer action bar: Copy · 👍 / 👎 with reason chips** (Wrong source, Out of date, Inaccurate, Wrong language, Too long). Log metadata only, never the message text. *Where:* the assistant turn footer in `Chat.tsx`, which today has only Retry. *Why:* Perplexity separates "Wrong sources" from "Inaccurate" [S]. That gives labelled failures for the eval set without storing text. *Check:* the event schema contains no message text.
5. **Per-card attribution and freshness line.** "Source: Wasalt.sa · collected 18 Nov 2026 · prices can change" on every card, not only in the footer. *Where:* `ListingCard` / `ProjectCard`, near `SourceLink`. *Why:* Zillow and Realtor.com keep MLS/broker attribution inside the card. Wasalt's `llms.txt` asks for attribution, as reported by C2 [S]. *Check:* every card shows a site and a date.
6. **Show the output checks that ran, per answer.** Inside "How I found this", list ✔ numbers matched source · ✔ no contact details · ✔ no advice language · ✔ language = AR. List only checks that actually run in `guardrails.py`, and never claim one that doesn't. *Where:* `Trace` in `Parts.tsx`. *Why:* C1's per-answer check list is the strongest trust signal among same-brief builds. Our trace shows intent, model, hops and latency, but not the checks. *Check:* a deliberately bad answer shows a failed check.
7. **Live step label while waiting.** "Searching projects… → Found 3 projects, 2 sources → Writing" collapses to "Completed 2 steps" when done. *Where:* the streaming state in `Chat.tsx` (status `waiting` / `streaming`). *Why:* Perplexity steps and Kagi tool dropdowns. It makes the free-model wait legible. *Check:* the label is visible before the first token and announced through the existing `aria-live` region.
8. **Compare from cards.** Add a "Compare" checkbox on each card; picking 2–5 builds the existing `CompareTable` with "Not published" gaps. *Where:* the cards in `Parts.tsx` plus a sticky "Compare (2)" button. *Why:* Rightmove compare takes up to 5 properties [V], and C3 lets users pick 2–3. Today compare only triggers from typed "X vs Y". *Check:* compare works without typing.
9. **One-line accuracy disclaimer under card rails, localised.** "Details can be wrong or out of date. Check the listing page before you act." *Where:* below `CardRail`, EN and AR strings in `lib/i18n.ts`. *Why:* OpenAI's shopping wording names the risky fields (price, availability) and points to the owner site [S]. *Check:* present on every card rail, in both languages.
10. **Fair-housing-style trap: steering by nationality, religion or family status** (e.g. "areas with no [nationality] residents"). Add a refusal template and eval cases in EN and AR. *Where:* `templates.py`, `guardrails.py`, `evals/cases.yaml` (new `trap` cases). *Why:* the only refusal policy the portals publish is fair housing (Redfin [V], Zillow [S]). It is an easy reviewer probe we don't test. *Check:* the new cases pass, with no false refusal on "family-friendly amenities".
11. **Mobile: sources and trace as a bottom sheet.** *Where:* `SourceList` and `Trace` at ≤ 640 px. *Why:* the Perplexity teardown recommends a full-width sheet on mobile, and the SPEC reviewer path is mobile-first. *Check:* no horizontal scroll at 360 px, and the sheet closes with Esc or a swipe.
12. **Card steering: "More like this / Not for me"** turns into a follow-up turn with an adjusted filter. *Where:* the card footer. *Why:* the ChatGPT shopping-research steering pattern [S]. Cheap to build because it only generates a chip message. *Check:* it produces a visible chip-like follow-up, not hidden state.
13. **Honest cold-start / quota screen with a timer**, plus one line on what still works in degraded mode. *Where:* `Chat.tsx` error and rate-limit states, which already have a `RATE_LIMITED` countdown. *Why:* C1's "Preparing the concierge" timer, and C4's upfront availability note. *Check:* the first load on a cold instance shows the state rather than a blank.
14. **README "Try these" table with a "What to look for" column** covering R1–R7, plus a 30–60 s GIF or video. *Where:* `README.md`, which is still a skeleton. *Why:* C5's table and C13's embedded demo. The reviewer reads the README second. *Check:* every row maps to an eval case ID.
15. **Map view behind `FF_MAP`**, only after 1–14. *Why:* Zillow and Redfin lead with maps, but this is the most work for the least trust gain at this stage. *Check:* off by default until it passes evals (SPEC D14).

## Where we already beat them

- **Cards, compare tables and calculator outputs are built in code from the database, and the LLM writes prose only** (SPEC D6). Among same-brief repos, only C2 and C3 build citations or cards in code. None publishes a **calculator that shows its formula and inputs**. Of the portals, only Realtor.com mentions affordability budgets [S], with no formula shown.
- **Explicit "Not published" cells** in compare. C3 is the only peer with an equivalent ("Not stated in source").
- **Arabic and RTL as a first-class path** (`dir`, `<bdi>` around prices and figures, Arabic chips). No Gulf portal publicly documents Arabic for its AI [U]. Most same-brief repos mention Arabic only in passing. C1 and C4 are the exceptions.
- **One container serves the frontend and API**, matching the brief literally. C4 splits it over two Render services and its Docker image covers the backend only.
- **A "How I found this" trace** exposing intent, path, tool, model, fallback hops, LLM calls, latency and cache hit. Only C1 is comparable, and C1 adds per-retriever counts and checks; see Steal #6.
- **Trap chip and boundary templates as part of the UI**, not only the evals. **A public `/evals` page that shows below-target numbers as measured** (`citation_rate` 0.88, `arabic_rate` 0.70). Only C1 and C4 are comparably candid.
- **Stop control and abort handling**, plus a retry that preserves input under rate limits. No peer README mentions stop.

**Where we are weaker (be honest about these):** we publish no retrieval metrics (hit@k/MRR or an
ablation; C1 does). The latest eval run had `llm_available: False`, so it measures only the degraded path.
C4 and C1 run live-model evals. We have no inline chips (C3 does) and no feedback capture (C3 does).

## Eval presentation (max 6 changes to `/evals` and REPORT.md)

1. **Show n and a 95% interval beside every rate.** For example: "Arabic 0.70 (14/20, 95% CI 0.48–0.85)" using Wilson intervals. Cluster by source page where cases share one. *Where:* the `/evals` category table and REPORT "Scores vs targets". *Source:* [Miller 2024](https://arxiv.org/abs/2411.00640). *Why:* with 5–30 cases per category, a "Met / NO" verdict without an interval overstates certainty in both directions.
2. **Put a run-condition banner first, and never mix conditions in the headline.** "This run: language model NOT available. Every answer used the code-built path." Publish a separate live-model run (`llm_available: true`) as its own column. *Source:* the OpenAI hub states its condition ("without browsing") [S], and C4 says what is "not claimed". *Why:* our latest run measured degraded mode only.
3. **Add a retrieval table: hit@1/3/k and MRR for BM25 only, dense only and hybrid RRF**, on the factual and Arabic cases. *Where:* a new section on `/evals` and in REPORT.md. *Source:* C1's ablation, and HELM's per-component reporting. *Why:* it is the one metric where a same-brief competitor is visibly ahead, and it justifies SPEC D11.
4. **Per-case drill-down for every non-passing case:** question, language, expected behaviour, an excerpt of the actual answer, failure reason, and a link to the raw JSON in `evals/results/`.
